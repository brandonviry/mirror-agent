# Registre des Bugs Connus & Contournements

Cette section constitue le **Pilier #8 (Limites connues, Bugs & Contournements)** de la documentation officielle de **Mirror Agent**.

Elle adopte une approche **Hybride synchronisée avec GitHub Issues** :
- Chaque bug possède une **Fiche Technique détaillée** dans cette documentation (symptôme, fichier et lignes exactes, cause racine, contournement immédiat et correctif cible).
- Chaque fiche est reliée bidirectionnellement à une **Issue GitHub officielle** sur [`brandonviry/mirror-agent/issues`](https://github.com/brandonviry/mirror-agent/issues) avec son état réel (**🟢 RÉSOLU / FERMÉ** ou **🔴 OUVERT**).

<Callout type="info" title="Pourquoi documenter les bugs ouverts ?">
Conformément aux invariants du projet (`AGENTS.md`), nous documentons en toute transparence les limitations actuelles de la codebase ainsi que leurs **contournements immédiats (*workarounds*)** afin qu'aucun développeur ne reste bloqué lors de l'installation, des tests hors-ligne ou de l'exécution des graphes.
</Callout>

| **[`BUG-004`](/docs/bugs/bug-004-state-import-crash)** | [Issue #4](https://github.com/brandonviry/mirror-agent/issues/4) | 🔴 **P0** | `src/retrieval_graph/state.py` (`L33`) | Crash `ValueError` dès l'import de `state.py` ou `graph.py` si `MEM0_USER_ID` est absent. | Définir `MEM0_USER_ID="default-user"` dans `.env` ou `os.environ` **avant** tout `import retrieval_graph`. |

| **[`BUG-006`](/docs/bugs/bug-006-retriever-provider-keyerror)** | [Issue #6](https://github.com/brandonviry/mirror-agent/issues/6) | 🟠 **P1** | `configuration.py` (`L35`) & `retrieval.py` (`L300`) | Désynchronisation `Literal["chroma"]` vs 5 backends + `KeyError` sur `__annotations__`. | Utiliser exclusivement `"chroma"`, `"elastic"`, `"elastic-local"`, `"pinecone"` ou `"mongodb"`. |
| **[`BUG-007`](/docs/bugs/bug-007-apply-reasoning-gemini-lockin)** | [Issue #7](https://github.com/brandonviry/mirror-agent/issues/7) | 🟠 **P1** | `src/retrieval_graph/graph.py` (`L284-312`) | `apply_reasoning` code en dur Gemini Thinking et envoie un payload `{"contents": ...}` invalide aux autres LLMs. | Définir `GOOGLE_API_KEY` ou forcer le routage vers `generate_response` si vous n'utilisez pas Gemini. |
| **[`BUG-008`](/docs/bugs/bug-008-gcp-credentials-import-crash)** | [Issue #8](https://github.com/brandonviry/mirror-agent/issues/8) | 🟡 **P2** | `utils/obsidian_monitor.py` (`L22`) & `gcp_logging.py` (`L17`) | Crash `DefaultCredentialsError` à l'import hors Google Cloud Platform. | Utiliser `IndexGraph` directement pour indexer Obsidian sans importer `obsidian_monitor.py`. |
| **[`BUG-009`](/docs/bugs/bug-009-eval-levenshtein-bias)** | [Issue #9](https://github.com/brandonviry/mirror-agent/issues/9) | 🟡 **P2** | `utils/eval_rag_pipeline.py` (`L56-58`) | Le score de similarité Levenshtein plafonne sous `0.05` face à des chunks de 3000 caractères (seuil `0.8` impossible). | Évaluer le pipeline via `exact_match_metric` en attendant le passage aux embeddings cosinus (RFC P3). |
