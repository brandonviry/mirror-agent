## 1. Symptôme Observé

Lorsque l'API Mem0 retournait une liste de souvenirs dont un seul élément possédait `"metadata": null` (désérialisé en `None` par Python) ou ne contenait pas la clé `"memory"`, `Mem0Memory.get_messages()` levait :

```text
AttributeError: 'NoneType' object has no attribute 'get'
```

De plus, même si 99 souvenirs sur 100 étaient parfaitement valides, le 100e souvenir malformé provoquait l'abandon des 99 messages déjà construits et retournait `[]`.

---

## 2. Cause Racine (*Root Cause*)

Le code initial présentait deux défauts cumulés :

1. **Piège classique de `dict.get("metadata", {})`** : En Python, `memory.get("metadata", {})` ne retourne la valeur par défaut `{}` que si la clé `"metadata"` est **absente** du dictionnaire. Si la clé est présente avec la valeur `None` (`{"memory": "texte", "metadata": None}`), `.get()` retourne `None`, et l'appel chaîné `.get("role", "user")` plante avec `AttributeError`.
2. **Bloc `try...except` englobant toute la boucle** : La boucle `for memory in memories:` n'avait aucune gestion d'erreur par élément ; toute exception sautait directement au `return []` final.

---

## 3. Correctif Appliqué (Commit `60c5871`)

Chaque entrée de `memories` est désormais traitée dans son propre bloc `try...except` isolé, avec validation stricte des types `dict` et `str` :

```python
for memory in memories:
    if not isinstance(memory, dict):
        continue
    try:
        content = memory.get("memory")
        if not isinstance(content, str):
            continue
        raw_metadata = memory.get("metadata")
        metadata = raw_metadata if isinstance(raw_metadata, dict) else {}
        role = str(metadata.get("role", "user")).lower()
        message_cls = MESSAGE_TYPES.get(role, HumanMessage)
        messages.append(
            message_cls(
                content=content,
                additional_kwargs=dict(metadata),
            )
        )
    except Exception:
        logger.warning("Skipping malformed memory entry: %r", memory, exc_info=True)
```
